# ThreadBeacon UI 优化提示词（agy CLI 复核版）

## 目标

优化 `apps/control-plane`，把 Dashboard、Studio 与 Skills 统一为以持续竞品研究为首个场景的团队工作台。参考 `opencli-Razormind` 的项目上下文、系统脉搏和行动式信息架构，但不照搬品牌、代码或重型依赖。保持现有 React 19 + Vite + 原生 CSS 技术栈，不引入大型 UI 库，不改变 API、安全校验、审计和 Worker 凭据边界。战略范围与能力缺口以 `docs/深度产品研究与战略决策.md` 为准。

## 真实能力边界

UI 只能呈现后端已经提供的能力：

- `/api/jobs`、`/api/schedules`：任务、租约状态、取消、重试与定时计划。
- `/api/studio`、`/api/workflows`：项目、来源、DAG 草稿、发布版本、运行与 Trace。
- `/api/records`、`/api/exports`、`/api/reports`：标准化记录、去重、搜索、导出与报告。
- `/api/skills`：版本化 Skill、九要素、运行证据、人工动作确认、纠错与回滚。
- `/api/browser`：受控浏览器 Profile、会话、动作、快照与截图。
- `/api/integrations/*`、`/api/mcp`：Dify、Webhook、PAT 与 MCP。
- `/api/governance`：交付规则和审计日志。团队管理能力可以进入“团队与系统”，但不打断研究员的项目、运行和报告主路径。

禁止虚构接口、假状态或未落地的自动化能力。平台密钥与浏览器登录态继续留在 Worker；PAT、Webhook 和邀请链接只在创建时显示明文。

## 视觉方向

- 关键词：研究情报、可信证据、运行可观测、克制高密度。
- 主色使用 Cobalt Blue；背景与导航使用 Slate/Charcoal；成功、等待、失败分别使用 Emerald、Amber、Crimson。
- 避免通用紫色 AI 渐变、霓虹发光、大面积毛玻璃和纯营销型留白。
- 卡片以 1px 边框和轻微阴影建立层级；圆角使用 6/8/12px 三档。
- 所有正文、辅助文本、徽标和时间戳的实际字号不得低于 11px；正文 13px，模块标题 15–16px，页面标题 19–24px，指标数字 24px。
- 间距使用 4px 基准网格：4、8、12、16、20、24、32、40px。

## 全局壳层

- Dashboard、Studio、Skill 共用同一个 248px 深色产品导航。
- 产品一级入口固定为：今天、项目、自动化 Skills。
- 当前模块的页内导航位于一级入口下方；API 文档和项目架构作为辅助入口。
- 不显示 Workspace、Owner/Editor/Viewer 或团队切换；连接状态和账号退出收敛到侧栏。
- 顶部工作栏高度 68px，展示页面标题、运行摘要、刷新和当前主操作。

## 组件规范

- Primary button：34–40px 高，蓝底白字，6px 圆角，不使用强投影。
- Input/Select：至少 38px 高，13px 字号，Slate 300 边框；焦点显示蓝色双层高对比轮廓。
- Status badge：至少 22px 高、11px 字号，包含状态点；运行中为蓝，完成/在线为绿，等待为琥珀，失败为红，取消/离线为灰。
- Modal/Drawer：必须有 `role="dialog"`、`aria-modal`、可读标题和明确关闭按钮。
- Secret reveal：使用琥珀色安全提示，明确“仅本次显示”，复制后提供短暂反馈。
- 后端返回只读状态时：保留顶层表单拦截，所有写按钮同时禁用，并展示直接原因；不扩展成角色管理界面。

## 页面要求

### 登录页

- `>= 1280px` 使用 45:55 双栏，左侧品牌叙事最小 460px，右侧表单最大 440px 且水平居中。
- `< 900px` 改为上下布局；`< 640px` 隐藏品牌长叙事，只保留登录主流程。
- 本地账号与 OIDC 只按 `/api/auth/methods` 返回能力展示。

### Dashboard

- 首屏使用紧凑、真实的系统脉搏，不使用伪造趋势图；随后展示“待处理”和“最近成果”。
- 待处理只由失败任务、离线 Worker、暂停计划等现有事实生成，不创建第二套状态。
- 保留任务流水线、节点、计划、记录、来源和报告。
- 任务状态、进度、错误和 Trace 操作必须一眼可分辨。
- 数据记录过滤、CSV/JSON 导出和原始 JSON 折叠内容保持完整。

### Studio

- 保留项目概览、业务编排、运行记录、结果与证据、执行资源、连接与能力、自动交付七个视图；移除团队与权限入口。
- 项目是来源、工作流、运行、证据和交付的聚合上下文；全局页面不复制一套项目后台。
- DAG 画布的节点尺寸、坐标和 SVG 锚点属于同一契约；修改其中一项时必须同步修改连线计算并回归多源汇聚。
- Agent、Gate、Filter 等节点配置只能使用后端 `WorkflowSpecPolicy` 支持的字段。
- Browser Profile 必须区分 anonymous/authenticated，并继续显示 CDP 证明状态。

### 自动化 Skills

- 强化不可变版本、运行证据、待确认动作和纠错提案四项摘要。
- 人工风险确认必须同时展示风险原因、精确动作 JSON、“批准一次”和“拒绝并终止”。
- 红线不得因 auto-confirm 或视觉隐藏而绕过。

## 响应式与无障碍

- `>= 1440px` 完整双/三栏；`1180–1439px` 收窄侧栏和页面边距；`900–1179px` 主导航转顶部横栏；`< 640px` 使用紧凑导航和单列内容。
- 工作流画布允许内部滚动，页面本身不得出现非预期水平溢出。
- 所有图标按钮提供 `aria-label`；所有交互元素具有 `:focus-visible`；支持 `prefers-reduced-motion`。
- 颜色不是唯一状态信号，状态同时显示文字或图标。

## 安全实施顺序

1. 先建立设计令牌、统一导航、有效字号下限与登录页布局，不改业务状态。
2. 再逐页标准化卡片、表单、状态与空态。
3. 最后拆分大组件；拆分时保持状态仍由原容器单向下传，避免工作流草稿和 Viewer 拦截回归。

## 验收

- `pnpm check` 全部通过。
- 1280px、900px、768px、640px 视口无非预期水平滚动、文本重叠或表单失衡。
- Dashboard、Studio、Skill 的品牌、导航、按钮、卡片、表单和状态语言一致。
- 任务取消/重试、工作流保存/发布/运行、Skill 确认/纠错、PAT/Webhook/Dify 和交付规则的原有请求契约不变。
