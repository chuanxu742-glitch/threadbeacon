# 社交聆听行业的合规范式 —— 可照抄的参照系

- 调研日期：2026-08-05
- 背景：客户全球化后，绑定约束从中国刑法变为 GDPR。本文回答"合法的同行是怎么做的"。
- 关联：`docs/技术选型调研.md` 第 16–17 节（辖区矩阵）

---

## 0. 核心结论

Brandwatch、Meltwater、Talkwalker、Sprinklr 这些全球合法运营的厂商，
和"爬虫"的区别**不在技术，在于对封闭平台走合同授权、只对开放网络爬取**。

合规架构是三层：

1. **封闭平台 → 付费官方数据许可**（X firehose、Reddit Official Data Partner、TikTok Marketing Partner 私有 API）
2. **开放网络 → 自爬**（新闻/博客/论坛/评论，按条数占数据量大头，法律风险最低）
3. **GDPR 层 → Art.6(1)(f) 正当利益 + Art.9(2)(e)「明显公开」**，配公开 DPA、Art.27 代表、数据主体权利通道

**被处罚和被起诉的案例，全部落在「对封闭平台无授权采集」或「无法律基础建库」两类，
与「爬公开网页」本身无关。** 这是最重要的边界。

## 2. 成本量级（决定新进入者能不能玩）

| 数据源 | 价格 | 可信度 |
|---|---|---|
| X 企业 firehose | **约 $42,000/月起** | 多方第三方口径一致，X 官方只写 "custom pricing" |
| Reddit 商业层 | 约 **$12,000/月 / 5,000 万次调用**，超额 $0.24/1K | 第三方口径，Reddit 无公开 rate card |
| Reddit 企业合同 | $50K–$500K+/年 | 未充分验证 |
| Bluesky firehose | **$0** | 开放协议 |
| 对照：Reddit → Google AI 训练许可 | 约 **$6,000 万/年** | 媒体报道 |

**X + Reddit 双授权全量的年支出量级在 $60 万–$100 万+，新进入者基本买不起。**

现实起步路径：按规则量订阅 X（非全量 firehose）+ Reddit 商业层 + 聚合器补开放网络。

## 3. 合规机制：Meltwater 是最完整的公开范本

Meltwater 专门有一份《被监控内容中数据主体隐私通知》，结构可直接照抄：

- **法律基础**：Art.6(1)(f) 正当利益；特殊类别数据引 **Art.9(2)(e)「manifestly made public」**
- **数据来源表述**："publicly available sources, including public social media platforms, websites and online newspapers"
- **公开 DPA + TOMs 附件**
- **Art.27 代表已具名**：EU = Meltwater The Netherlands B.V.（阿姆斯特丹）；UK = Meltwater (UK) Limited（伦敦）
- **权利通道**：privacy@meltwater.com
- **区域化差异**：德国记者数据改用「同意」基础

> **注意其缺口**：该通知**不披露采集方式是许可还是爬取**，也不声明 ToS 合规。
> 说明行业实践在这一点上是模糊处理的，不宜当作"完全无风险"的证明。

Brandwatch/Cision 有 Data Privacy FAQs + ISO 27001:2022；Talkwalker 有公开 DPA PDF。

### 监管方的最新立场
- **EDPB Opinion 28/2024**（2024-12-17）：正当利益是爬取的唯一现实基础，但须通过 LIA 三步测试
- **EDPB Guidelines 03/2026**（2026-07-07 通过，公开咨询至 2026-10-30）——**很新，需持续跟踪**
- **"公开发布 ≠ 同意被采集"**；比利时 DPA 明确：公开数据不因公开而失去 GDPR 保护

## 4. 反面案例：踩线的具体位置

| 案例 | 结果 | 核心违法点 |
|---|---|---|
| **Meta v. Voyager Labs**（2023） | **和解**：永久禁令 + 永久删除数据 + 付款 | 创建 **3.8 万个假账号**，**登录态**爬 60 万+ 用户 |
| **Meta v. Bright Data**（2024-01-23） | **Bright Data 胜诉**，Meta 2024-02 撤诉 | 认定："ToS 不禁止**登出状态**爬公开数据，更不禁止转售" |
| **X Corp v. Bright Data** | 2024-05 驳回 → 2024-11 部分复活 → 2025-04 Bright Data 反垄断反诉存活 → **2025-06 和解**（条款保密）| X 修改 ToS 全面禁爬被质疑构成对"公共广场数据"的垄断 |
| **CNIL v. KASPR**（2024-12-05）| **罚 €200,000** | 爬 LinkedIn 建 1.6 亿联系人库；**无视用户可见性设置**、不履行 Art.14 告知与 Art.15 访问权 |

> Meltwater / Brandwatch / Talkwalker 被 DPA 处罚或调查：多轮检索**未发现**公开记录。
> 标记为"未发现证据"，不等于"确认没有"。

### 这四个案例连起来看，边界极其清晰

**Voyager Labs 和 Bright Data 是同一条线的两侧**：
- Voyager 建假账号、**登录态**爬 → 永久禁令
- Bright Data **登出**爬公开数据 → 胜诉，连转售都被认可

**这直接印证主报告 §17.1 的结论：登录态采集是唯一一个换辖区也不会变好的选择。**
它恰好是 Meta 唯一告赢的那种行为。

## 5. 2026 新进入者的可操作采购清单

### A. 可直接买到 / 免费拿到
- **Bluesky**（AT Protocol firehose，免费）
- **Reddit** Data API 商业层 → 再申请 Official Data Partner（审批 2–4 周，自助注册已关闭）
- **YouTube** Data API v3（配额制，search 需扩容）
- **X** 企业 API（直签销售）
- 新闻/博客/论坛/评论 — 自建爬虫或买 Datastreamer 类聚合器

### B. 只能靠伙伴资格换，不能单买
- **TikTok** — 必须先通过 TikTok Marketing Partner 审核，才能申请 Mentions API。
  **这是新进入者最大的结构性壁垒，周期长，应尽早启动。**

### C. 基本拿不到，产品上必须明确降级
- **Facebook / Instagram 全网公开内容** — 无任何商业许可通道。
  只能做「客户自有资产（Graph API）+ 广告库」，**不要承诺全网监听**
- **LinkedIn** — KASPR €200,000 就是判例
- **Threads** — 与 Meta 同源，商业通道未验证

### ⚠️ Bluesky 实测更正（2026-08-05）

初稿把 Bluesky 整体写成"零成本拿到完整 firehose"，这个说法不够精确。
同一网络、同一代理下实测：

| 端点 | 结果 | 含义 |
|---|---|---|
| `app.bsky.actor.getProfile` | HTTP 200 | 公开读取无需授权 |
| **`app.bsky.feed.searchPosts`** | **HTTP 403** | **历史检索需要会话凭据** |
| **Jetstream (`wss://jetstream2...`)** | **连上即收到事件** | **实时流确实无需授权** |

Bluesky 的会话凭据是 app password，属**用户凭据**，本项目类型层面不支持。
因此 Bluesky 可用，但**只能订阅实时流、拿不到历史**——这是不同的获取形态
（`AcquisitionMode: 'streamLive'`），做话题覆盖需要持续订阅而非一次查询。

"firehose 免费"本身没错，错在初稿把它默认成了"检索也免费"。
教训：调研阶段读到的"开放/免费"要落到**具体端点**再下结论。

### D. 落地顺序
1. 先用 **Reddit + Bluesky + 开放网络**跑通产品（成本最低、授权最干净）
2. 有收入后加 **X 按规则量订阅**，暂不上全量 firehose
3. **同步启动 TikTok Marketing Partner 申请**（周期长）
4. Meta 侧只做「自有资产 + 广告库」

### E. 合规红线（照抄头部厂商的边界）
- 不建假账号
- **不用登录态爬封闭平台**
- 不绕技术防护
- 尊重用户可见性设置
- 不推断特殊类别数据

**首日就要有**：公开 DPA、Art.27 EU/UK 代表、被监控数据主体专项隐私通知、
书面 LIA（正当利益评估）、可用的删除/反对响应通道。

## 6. 对本项目的直接含义

原计划的 10 个平台，按本节标准重新分档：

| 平台 | 结论 |
|---|---|
| Reddit、Bluesky（新增）、YouTube | **立即可做**，授权干净、成本可控 |
| X | 可做，但先用按量订阅，别上 firehose |
| TikTok | 先申请 Marketing Partner，拿到再做 |
| Instagram | 降级为「客户自有资产」，不承诺全网监听 |
| 抖音、小红书、快手、B站、微信视频号 | **无合规通道**，见主报告 §10。
产品上标注不支持，或只做用户授权自有账号数据 |
| 电商（淘宝/京东/拼多多）| 见主报告 §13，只做自有店铺 |

**注意这个清单里 Bluesky 是新增的**——它免费、开放、无授权门槛，
是唯一一个可以零成本获得完整 firehose 的主流社交平台，
对一个还没有收入的新产品来说，价值被严重低估。
