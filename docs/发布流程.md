# 开源发布流程

1. 从干净的 `main` 运行 `pnpm check`，确认 `git status` 无未提交文件。
2. 核对 `ROADMAP.md`、`docs/兼容矩阵.md` 和 `CHANGELOG.md`；未真实验收的能力继续标为未验收。
3. 确认 `LICENSE`、`NOTICE`、`DISCLAIMER.md`、依赖锁文件和容器基础镜像版本。
4. 创建签名或受保护的 `vX.Y.Z` tag。tag 会触发 `release-images.yml`，向 GHCR 发布 control-api、control-plane、worker、gateway、browser 的 amd64/arm64 镜像。
5. 在两种架构上分别启动 Compose、创建任务、写入报告、执行备份，并从隔离目标恢复。记录镜像 digest 和验收证据。
6. 只有五个镜像和两种架构全部通过，才创建 GitHub Release；发布说明必须列出 Gateway 单副本、Dify 沙箱、凭据型 Provider 和 CDP 的限制。

手动运行镜像工作流只会推送 `edge` 标签，适合预发布验证；正式发布使用不可变版本 tag/digest，不使用 `latest` 作为回滚依据。
