# ThreadBeacon：项目背景、问题与架构

## 项目背景

研究团队需要同时观察社交平台、公开网站、官方 API 和自有账号数据。传统方案通常由零散脚本、浏览器操作、表格和一次性提示词组成：数据字段不一致，运行失败难以恢复，模型结论无法回到原始证据，登录态与平台密钥也容易扩散。

ThreadBeacon 是一个 Apache-2.0 开源、可自托管的研究情报工作流平台。它不把“抓到数据”当作终点，而是把来源治理、持续采集、标准化、分析、证据关系、审计和交付组成一条可重复运行的流水线。

## 解决的问题

1. **来源碎片化**：以 `Platform × ProviderKind × AcquisitionMode` 契约统一开放协议、官方 API、授权自有账号、RSS、REST、Web 和 OpenCLI 来源。
2. **流程不可复用**：项目保存来源、DAG、计划任务、版本和交付规则；任务支持租约、重试、取消和恢复。
3. **AI 结论不可复核**：报告中的主题连接到标准化记录、原文 URL、运行检查点、模型/Skill 版本和事件 Trace。
4. **凭据与访问风险**：平台密钥和浏览器登录态留在 Worker；控制面负责身份、角色、scope、审计和能力路由。
5. **部署边界不清**：Docker 可选；原生、Compose 和单 Gateway/多 Agent 架构分别记录真实兼容性与限制。

## 后端架构

```text
React 管理台 / MCP / API Client
                │ HTTPS · 站内登录（Basic/OIDC）/ PAT
                ▼
Spring Boot Control Plane
  身份与工作区 │ 任务/租约 │ DAG/Skill │ 审计/交付
          │                         │
          ├── PostgreSQL：状态、记录、证据、审计
          └── S3/MinIO：报告、截图、GEO Trace
                │ outbound polling / HTTPS / WSS Gateway
                ▼
TypeScript Worker Fleet
  能力发现 │ 抢单 │ 重试 │ 执行 │ 结果回传
          │
          ├── 开放协议 / 官方 API / 授权 Provider
          ├── RSS / REST / Web（SSRF 与 robots 防护）
          └── Browser Profile / CDP（登录态留在节点）
```

- **Java 控制面**：Spring Security 身份认证，viewer/editor/owner 授权，任务租约、工作流状态机、Skill 治理、Flyway 数据迁移、审计与投递。
- **认证入口**：Web 登录页先读取 `/api/auth/methods`，只展示当前部署真正启用的本地账号或 OIDC；API 的未认证响应保持 JSON 401，避免浏览器原生认证弹窗。
- **TypeScript Worker**：只上报本机真实具备的能力；控制面不会把任务派给未配置密钥、CDP 或 Provider 的节点。
- **PostgreSQL**：保存任务、计划、工作流、检查点、标准化记录、证据关系、成员与审计。
- **S3/MinIO**：保存完整报告、截图和 Trace 等大对象。
- **Reverse Gateway**：让 NAT 后的 Agent 主动建立 WSS；当前协调状态在单进程内存中，因此 Gateway 保持单副本。

## 核心流程节点

| 节点 | 作用 |
|---|---|
| Source | 按平台能力路由采集任务，保存 provenance 和增量游标 |
| Normalize | 把平台字段转换为统一 `SourceItem` |
| Dedupe / Filter | 跨任务去重，过滤不符合研究范围的内容 |
| Gate | 规则阈值或人工确认；风险动作默认停下等待批准 |
| Cluster | 将大量表达归并为可解释的问题主题 |
| LLM | 对聚类结果做有界总结，拒答或格式错误不会伪装成完整结果 |
| Agent | 按版本化 Skill 多步执行，保留里程碑、自评、纠错和回滚证据 |
| Report / Dataset | 生成证据报告，并沉淀为可查询数据资产 |
| Deliver | 经 Webhook、飞书、钉钉、企业微信或邮件网关交付 |

完整生命周期为：定义项目 → 接入来源 → 标准化与去重 → DAG 分析 → 建立证据关系 → 报告与自动交付。

## 明确边界

- 不包含平台签名逆向、DRM 绕过、虚假账号或任意 JavaScript/eval。
- Dify code/tool/plugin 在强隔离沙箱完成前保持阻断。
- OpenCLI 浏览器能力必须有真实 CDP/Profile 证明；GEO 只能使用匿名干净 Profile。
- 开源软件提供技术能力，不代表平台授权或在所有辖区均可使用。
