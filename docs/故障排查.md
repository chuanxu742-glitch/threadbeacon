# 故障排查

先运行 `pnpm control:doctor`。它会检查 Node、Java、PostgreSQL、S3/MinIO 和端口；Docker 不是原生启动的前置条件。

| 现象 | 检查与处理 |
|---|---|
| Web 3000 打不开 | 确认 `pnpm control:native` 仍在运行，检查 3000 是否被其他进程占用 |
| API 401/浏览器弹窗 | 使用 `.env.local` 的 Basic Auth；PAT 必须带 `Authorization: Bearer threadbeacon_...` |
| Worker 不在线 | 检查 API 8080、注册密钥、节点状态文件权限和 Worker 日志；首次注册后改用节点 ID/token |
| 任务一直 queued | `/api/v1/capabilities` 中没有对应在线能力；通常是 Provider 凭据、CDP 或授权插件未配置 |
| LLM 任务失败 | 配置 `OPENAI_API_KEY`/兼容端点或 Anthropic 凭据；`fetchOwned` 连接测试不依赖 LLM |
| RSS/Web 报私网或保留地址 | DNS 解析到了私网、链路本地或保留地址，属于 SSRF 防护；修复 DNS/代理，不要关闭校验 |
| OpenCLI 浏览器能力缺失 | 配置 `OPENCLI_CDP_ENDPOINT`，完成 Profile attestation，并确认 `opencli doctor` 可连接 |
| GEO 能力缺失 | 除健康 CDP 外，还需匿名 Profile 和空 Cookie attestation；不能复用登录态 Profile |
| `fetchOwned` 一直排队 | 安装实现该平台 `fetchOwned` 的用户授权 Provider；API 只负责安全排队，不伪造平台授权 |
| Dify 导入后不能发布 | code/tool/plugin/agent/loop 节点会变成阻断 gate；替换为受支持节点，或部署经过审计的强隔离沙箱 |
| Gateway Agent 反复重连 | 核对 WSS 地址、Agent token 和时钟；公网不得使用明文 WS，单 Gateway 不可横向扩容 |
| 报告元数据存在但下载失败 | 检查 S3 endpoint、Bucket 与凭据；恢复时数据库与对象必须来自同一备份点 |
| Flyway 启动失败 | 不要手改迁移历史；在备份副本核对版本和 SQL，再恢复或升级 |

日志和错误会隐藏常见 token，但排障输出仍可能包含业务数据。提交 issue 前请删除 URL 查询参数、账号标识、原文和本地路径中的敏感信息。
